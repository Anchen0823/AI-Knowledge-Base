# 私人知识库

把收藏的视频整理成能读、能查、能追到原文的笔记。全部跑在本机，只有你一个人能打开。

B 站上的单条视频都可以往里加：粘贴链接就行，不用改配置、不用重启。目前已经整理过两条：贪吃蛇《退路》（`BV1QTHA6DELc`）和一条 AI 日报（`BV1kind6mER6`），这两条是人工逐条核对过的样例。只支持 B 站，不接受其他站点；一次只处理一个 P。

## 怎么打开

双击 **启动知识库.cmd**。终端里会打出一行这样的地址，浏览器也会自动打开：

```
本机打开：http://127.0.0.1:8765/#key=一串口令
```

- 口令就在地址 `#key=` 后面，每次启动都会换新的。整条地址复制进浏览器就能直接进，不用手动贴口令。
- 关闭那个终端窗口，服务就停了。
- 端口被占用时会自动换一个端口，窗口里会告诉你换成了哪个，不用自己查。

想换个方式启动（比如临时换个资料目录）：

```powershell
.\.venv\Scripts\python.exe -m snakekb.web --open                 # 默认端口 8765
.\.venv\Scripts\python.exe -m snakekb.web --port 8800 --no-proxy  # 指定端口、模型调用不走代理
```

## 四个页面

| 页面 | 看什么 | 能做什么 |
| --- | --- | --- |
| 百科 | 当前这份资料的完整笔记 | 读概览、适用条件和局限、分段摘要、逐条笔记；点出处编号看原视频时间点或截图；资料多于一份时可切换 |
| 书架 | 所有已入库的资料 | 看每份的摘要，点「阅读笔记」进入百科 |
| 知识地图 | 跨资料的知识点关系图 | 拖动节点、滚轮缩放、搜一个词、点节点看定义和原文证据、按连线密度筛关系 |
| 待处理 | 没整理完的任务 | 看卡在哪一步、为什么停；勾选同意后重新开始 |

侧边栏底部写着「看书和搜索不联网」，这是真的：浏览笔记、本地语义搜索、知识图谱都只读本地文件。只有整理新视频、以及入库时整理概念，才会把截图和画面文字发给本机已登录的 Codex 服务。

## 在网页里粘贴链接

页面顶部的输入框接受视频链接或 BV 号：`https://www.bilibili.com/video/BV…`、`b23.tv` 短链、或者直接贴 `BV…`。提交后有三种结果：

- **已经入库 / 已经在处理** → 直接跳过去看，不重复花模型额度。
- **还没勾选「允许 Codex 分析」** → 只记下这条链接和它的标题，不下载也不处理。想真跑就展开「导入选项」勾上再提交。
- **勾选并提交** → 后台开始取素材、分析。可以关掉网页，处理会继续；关终端窗口才会停。

新链接第一次进来时，会按素材自己的样子选一条路：

1. 有平台中文字幕 → 直接用字幕核对，最准；
2. 没有字幕但有人声 → 本机 faster-whisper 转写，音频不出本机；
3. 没有人声、只有背景音乐 → 逐秒识别画面文字。

走完这条路，标题和真实时长会记进 `data/sources.json`，之后这条视频就跟样例一样有确定的身份。处理到一半停下来时，「待处理」会写清停在哪一步和原因；已经拿到的材料都留在 `data/pending`，不会丢，修好之后接着跑即可。

想让某条新来源也像样例那样「发布前必须看到某些条件」，在 `data/sources.json` 里给它加 `"topics": ["条件一", "条件二"]` 即可；不写就不限定主题，只要求每条论述都能追到出处。

## 用命令行导入

```powershell
.\.venv\Scripts\python.exe -m snakekb.ingest --source https://www.bilibili.com/video/BV1WWNx6tcd5/ --allow-cloud-analysis
.\.venv\Scripts\python.exe -m snakekb query     # 只读查询正式笔记
```

- 想看清每一步，用 `python -m snakekb <命令>`（`fetch` / `status` / `prepare` / `run` / `gate` / `publish` / `query`），都可以带 `--source`。
- `--allow-cloud-analysis` 是必须的：不加就只下载素材，不生成笔记。这个参数等于你同意把截图和画面文字交给 Codex。
- 本机转写模型默认 `small`，可以用 `--asr-model medium` 换更大更准的，代价是更慢。
- 模型子进程默认走 `http://127.0.0.1:65532` 代理，可以用 `--proxy` 换，或者加 `--no-proxy` 不走代理。系统代理和 Codex 全局配置都不会被改动。
- 整理中途停了想重来，用显式的重试，**下载手动重试不限次数，旧记录和已用额度不会被清零**：

```powershell
.\.venv\Scripts\python.exe -m snakekb run --job data\pending\BV1QTHA6DELc\visual-e337394590c6ab3c --allow-cloud-analysis --retry-analysis
```

模型调用从第一条请求起使用 HTTPS，继续使用配置的代理；分段分析和概念整理均不设本地总等待时限。一个任务累计最多 16 次调用；服务或网络报错后暂停，不自动重放已经发出的调用。

第一次在本机装向量模型（约 24MB，装完日常使用不需要联网）：

```powershell
.\.venv\Scripts\python.exe -m snakekb.install_vectors --proxy http://127.0.0.1:65532
```

## 数据放在哪

| 路径 | 内容 |
| --- | --- |
| `data/formal/` | 正式资料，一份一个目录（笔记、截图、概念、来源信息、发布检查结果） |
| `data/formal/index.json` | 决定百科、书架、地图对外显示哪一版 |
| `data/pending/` | 待处理任务的全部中间产物；这些内容不会出现在三个正式页面里 |
| `data/sources.json` | 新来源的登记表（第一次加入样例之外的来源后出现）：标题、时长、字幕形态、可选的条件主题。删掉只影响这些来源要重新登记，已入库的资料不受影响 |
| `data/vectors/` | 本地向量缓存，按资料版本和论述内容增量更新 |

## 检查与测试

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v   # 62 项
.\.venv\Scripts\python.exe validation\final_audit.py          # 正式产物完整性审计
node validation\ui-smoke.js --port 8765 --token <口令>         # 真浏览器界面检查，13 项
```

`ui-smoke.js` 用系统里已装的 Chrome 或 Edge 直接驱动，不需要安装 Playwright。它会真的点开四个页面、点开截图、搜索知识点、从知识点跳回笔记原文、检查词条里的分组名和条件标题是不是人话，并把手机宽度下被裁掉的内容也一并报出来；截图存在 `output/playwright/`。

`validation/` 下另外几个 `*-browser-check.js` 是早期用 Playwright 写的流程脚本，界面文案已经同步到当前版本，但需要另行安装 Playwright 才能跑。

## 已知限制

这些限制是有意保留的，不是待修的 bug：

- 画面按每秒一张、每 5 秒一张全屏采样。极短的画面变化可能没被选中，OCR 也可能认错字。覆盖检查只能说明「材料读全了」，不能说明作者的结论正确。
- 笔记里区分「原作者陈述」「整理者分析」和「来源局限」。原视频里说法冲突或没讲清的地方，照原样保留，不替作者下结论。
- 语音转写出现过疑似幻觉，那批结果被隔离，没有混进正式笔记。
- 两条样例之外的新来源没有预设的条件主题，发布检查只保证「每句话都能追回原文」和「材料被完整读过」，不保证挑对了该核对的条件。想卡住某类条件，在 `data/sources.json` 里给它写 `topics`。
- 按用户授权，导入不设本地模型调用次数、截图总数、字幕文件大小、OCR视频时长或处理总超时预算。仍分批处理并保留引用、覆盖和失败检查。
- 局域网/手机访问只做了布局验证，实际手机连接和防火墙策略没有实机验收。默认只监听本机，不要映射到公网。
- 概念整理失败不会自动重跑：不设次数上限，失败仍暂停并保留现场。

### 可演化领域分类

知识图谱中的「管理领域」支持多标签自动归类，以及新增、拆分为子领域、合并和撤销。归类在读取正式资料时更新，依据标题、概念名称和定义中的关键词；没有概念提取结果时使用正文。新领域自动获得稳定 ID 和颜色，合并保留首个领域的 ID 和颜色。

系统根据跨资料共享概念生成新领域或子领域建议，并根据至少三份资料的领域归属重合率生成合并候选。这些是启发式建议，不代表主题已经被证明等价；需预览并确认后应用。界面预览显示实际归属变化，过期的分类版本会拒绝写入。未识别的主题保留为未分类，可手动新增关键词。

分类配置、变更前后快照和撤销记录保存在本地 `data/taxonomy.json`，不推送到 GitHub。浏览与调整分类不调用云端模型；撤销或更改规则后，当前资料与图例自动重新计算。
